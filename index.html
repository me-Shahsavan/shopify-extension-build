Technical Product · Case Study

Fixing a slow developer inner-loop on Shopify

Shopify's native hot reload for theme extensions is unreliable, and assets must be flat. Together they forced a slow edit → build → wait loop. A watch build made it instant.

The inner loop was killing team velocity

The solution

A build step absorbs the constraint — once, centrally

The nested tree is the source of truth. The pipeline compiles, bundles in dependency order, minifies, and writes the flat output Shopify expects. Developers never touch the flattening.

The transform

Flattening is deterministic & reversible

A nested path becomes a flat filename by replacing separators — so you can always read where a flat file came from. No collisions, no magic.

Nested sourceFlat asset
shared/loader/widget-loader.ts→shared-loader-widget-loader.js
widget-a/modules/init.ts + siblings→widget-a.bundle.js
widget-a/styles/*.css→widget-a.bundle.css
The win

From manual build loop → instant on save

BEFORE

edit → build → wait → refresh

Manual build on every change. Shopify's hot reload flaky — full-page reloads, changes that didn't show. The loop ran dozens of times a day, per developer.

AFTER

just save — it's already there

The watch build finds the bundle that owns the changed file, rebuilds it in dependency order, and writes the flat asset the page actually loads. Deterministic, every time — and a compile error prints and keeps watching instead of killing the loop.

The core: watch build

Save → rebuild the owning bundle → flat output

This is the heart of the fix. On every save, the build finds the bundle that contains the changed file, recompiles it in dependency order, and rewrites the flat asset the storefront loads. The developer never thinks about the flattening — or about Shopify's broken hot reload.

Design decisions

The choices that made it reliable

01

Explicit dependency order

Bundles list files in load order — not alphabetical globbing. Implicit ordering breaks silently in production.

02

Two file classes

Most files get bundled; a few are referenced directly from Liquid and can't be — the config makes that split visible, not buried.

03

Flattening that fails loudly

Path separators → dashes, so you can trace any flat asset back to its source. Two sources landing on one name aborts the build instead of overwriting an asset in production.

04

Watch as a first-class DX

The inner loop determines daily velocity, so the watch build is designed for speed, not bolted on.

Why it's a product decision

Pay the complexity once, not per-feature

The constraint is Shopify's. The cost lands on developers — and slow, error-prone builds quietly tax every feature shipped afterward. The trade I chose: add one build step to maintain, to buy a clean modular source tree whose benefit compounds on every future change. For a growing widget platform, that's firmly worth it — the alternative is a flat folder that gets worse every week.

Self-contained HTML — no build, no dependencies. Genericized for portfolio use.
